System context (C4 level 1)

Two kinds of people, one system, and two external services that are links, not integrations.

Project lead Student DevMatch (what we build) External: link only, no API call
No arrows go back. DevMatch never calls Telegram or GitHub. It validates a username or a URL and renders a link. If either service is down, nothing in DevMatch breaks. See integrations.md.

Containers and layers (C4 level 2 + ADR-0009)

One Node process on a free PaaS serves the SPA and /api. Inside the API, requests go down through layers; business rules live in one place.

Containers API layers (ADR-0009) Database Shared library (imported by both)
Only one box touches availableSpots. services/applications changes the counter inside a transaction with a conditional update (ADR-0007). Routes parse and validate, services decide, serializers choose what leaves the server.

The intersection: a student applies, the lead approves, the contact appears

Where the two user journeys meet. Press play, or click a step.

One transition, two entities, one transaction. Approving changes Application.status and Role.availableSpots together. The conditional UPDATE … WHERE availableSpots > 0 is what makes two leads racing for the last spot safe: the second one gets 409 ROLE_FILLED.
